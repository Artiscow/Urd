# Backlog

This is the running task list for Urd's development: concrete tasks, bug fixes and suggestions. [ROADMAP-en-GB.md](languages/ROADMAP-en-GB.md) owns the phases and the goals; this list owns the concrete tasks. Move things between the sections as needed, and strike an item with `[x]` when it is done (finished items are cleared out at a release). New milestone items get a «Done when:» line with observable conditions.

Fully finished milestones (e.g. v0.a.xyz) are cleared out at the releases; see [CHANGELOG.md](CHANGELOG.md) for what was delivered. Incoming suggestions and findings are sorted straight into the milestone or the phase where they are best taken; documented limitations without a plan stand in a section of their own at the bottom.

An entry inherits the number of the backlog item the work belongs under, plus one digit for order (0.6.6.5 → 0.6.6.5.1, 0.6.6.5.2 …). The digit is added only when the milestone gets more than one commit: if the whole milestone lands in one commit, the number is the milestone's own (0.7.1), and later commits under the same milestone continue at 0.7.1.2. The phase's standing item is four-part (0.7.0.x).

## Known Limitations (documented, no fix planned)

- Pictures from a Nextcloud share or a JSON list are proxied at their stored size (only Google's picture host resizes on request); the 12 MB cap applies, and the photo guide asks for sensibly sized files (review note, 0.7.0.16-35p)
- The preview hides the page's scrollbar, so browsers with a classic scrollbar lay out the published page about 15 px narrower than the preview shows (ADR-0018, 16 September 2026)
- In a window about 1024 px wide with the sidebar of words and a panel open, the canvas is about 560 px, so the floating element menu has no room beside a block and covers part of it, the least it can (`placeBesideBlock` and `wideFits` in `lib/menu-place.js`); the docked forms of «Element menu» keep the block in view (the walk of 0.7.33.9, 9 November 2026)
- Undoing a publish that is a merge commit restores the first parent's content (documented in `functions/api/github/revert.js`); rare through the editor, possible when someone also works through git
- «Undo the last publish» finds the last publish by its changes under `content/`, so a commit that touches only `media/` or the pages' routing copies (possible through git, never through the editor) cannot be undone from the editor
- Publishing from ANOTHER admin tab in the deploy window after an engine update (about a minute) can write the pages' routing copies from the old root index still served, which points at the deleted engine folder; the subpages then stand dead until the next publish (found in the bug hunt of 5 August 2026). The same tab is guarded, since publishing is blocked while the update rolls out, and the conflict check warns of the overlap in other tabs, but its warning does not say an update is the cause. It heals at the next publish; a guard across tabs needs shared state (a BroadcastChannel or the like)
- The whole engine folder takes a new name at every release, even when no engine file changed (ADR-0013): naming each file by its content, as `media/` does, needs a build step, since the engine files point at each other and one renamed file would rename every file that points at it. Visitors therefore load the engine again once after each update, even when it is byte for byte the same; a softening for docs-only releases is a v0.9 item
- The updater treats the template's own example pages' routing copies as Urd's files (found in the push review of 5 August 2026): where the owner deleted an example page (kaker, say), the next update restores its routing copy without the page, a live address to an empty page; where the template drops an example page whose slug the owner reused, its route is deleted without a word. The next publish repairs both, since it writes the copies from the site's page list
- The updater takes a site's `_headers` for unedited where it equals any release's own ([ADR-0014](adr/0014-updater-model.md) decision 5), so an owner who undoes exactly what one release changed, comments included, gets the newer file written over it at the next update; nothing in the file tells the two apart, and «Keep mine» on «Security headers» holds it back (27 November 2026)
- The calendar block shows a calendar kept elsewhere (an iCal feed), which holds no state and no coordinates: it cannot take sign-ups with a capacity or a waiting list, sell tickets, or show all its events on a map. Its «Sign up» button leads to whatever page the organiser has put in the event
- A crop made in the image editor in the phone view gives the block its shape on the phone at the phone width it was made at: a pinned block's rows and a flowing block's own height are fixed in px, so a wider or narrower phone shows a slightly different part of the picture
