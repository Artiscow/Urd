# ADR-0017: Optional AI integration via a local MCP server

Date: 10 August 2026. Status: accepted (v0.7; the read part is built in v0.8, the write part in v0.9).

## Context

«External AI service» has until now appeared in one place in the project: in [ELEMENTKART.md](../sammenligning/ELEMENTKART.md) part 7, as a rejected core dependency, with the AI wizard as the lowest priority in part 5a with the justification «requires an external service, against dependency-free». The field has moved since the map was written on 27 July 2026. In 2026 Sanity, Contentful, Storyblok, Strapi and Payload all shipped MCP servers, and an MCP server has become table stakes for a CMS: it lets the site owner's own agent client (Claude Code, VS Code, Cursor) read and edit content directly.

That changes the premise of the rejection. The objection concerned an external SERVICE that Urd depends on. An MCP server is not that: it is a local process in the site owner's own cloned repo, which calls nowhere, stores no key and is not part of the built site. The model is the site owner's own, chosen by the site owner, run by the site owner's own client. Urd never becomes an intermediary.

Urd is moreover unusually well positioned for this. The cloned repo IS the website (ADR-0004), the content is JSON with schemas in `schema/`, the sections are built from named presets, and the publishing guard in `template/functions/_lib/guard.js` is already exactly the permission model an agent should have: content, never code. Most of an MCP server for Urd is a thin layer over things that already exist.

Two alternative routes were considered and set aside for now. An AI assistant inside `/admin` against a user-configured endpoint presupposes an extension point admin does not have (`provides` in the plugin manifest delivers blocks, presets, backgrounds and templates to the SITE, not panels to admin) and raises key management as its own security analysis. The browser's built-in AI (Chrome's local model) is cheap and privacy-friendly, but Chromium-only, and the most tempting APIs (Writer, Rewriter, Proofreader) are in origin trial and therefore not stable.

## Decision

1. **AI is always optional and always outside the core.** No Urd feature, no built site, no publish, no test and no editor surface shall depend on an LLM. If the `mcp/` folder is deleted, Urd works bit for bit unchanged. The invariant is made machine-checkable: nothing outside `mcp/` and its own tests imports from `mcp/`, and CI never runs the server as part of build or publishing. The real danger is not an `import` but gradual leaning, so the setup guide places the chapter under «optional» and never in the main flow.

2. **The primary route is a local MCP server in `template/mcp/`, dependency-free, raw JSON-RPC over stdio without an SDK.** We implement the smallest surface there is: `initialize`, `tools/list` and `tools/call`. The server NEVER makes network calls and NEVER does git operations; it writes files, and the site owner commits and publishes themselves. Deprecated capabilities (roots, sampling, logging) are never implemented. The protocol version is one pinned constant with its own test and a dated comment.

   The reasoning for dropping the SDK: over stdio, MCP is line-delimited JSON-RPC 2.0 messages, on the order of 120 lines to handle. Everything else the SDK provides (HTTP transport, sessions, header-based routing, authorisation) we do not use, and the stateless-core changes in the 2026-07-28 specification concern the HTTP transport, not stdio. An npm dependency would thus have cost Urd's central promise for zero functional gain. `editor/` remains the only place in the repo with npm.

3. **The write permission is `guard.js`, not a new model.** The server reuses `isAllowedPath` from [template/functions/_lib/guard.js](../../template/functions/_lib/guard.js) and narrows it further, so the effective write surface is only `content/**.json` and `content/theme.css`. The MCP layer additionally refuses `media/**` (binary files make no sense for an agent) and `plugins/plugins.json` (enabling a plugin is a decision to run code, and belongs in admin). We never build a second permission model for AI.

4. **The model never shapes data.** There is no `urd_page_write(json)`. All structure is built by the engine's own factories: `create()` and `item()` in `sections/presets.js`, `defaults()` per block type, `buildPagePreset` in `page-presets.js`. The model chooses WHICH preset, not what a section looks like. Everything that does not come from a factory is validated field by field (known key, correct type, numbers within the grid limits), every mutation passes a dependency-free structure check before it hits disk, and `apply` is opt-in: without it only a diff summary is returned.

5. **The version coupling is structural, not maintained.** The server finds the site root with `new URL('..', import.meta.url)` (which hits `template/` in the monorepo and the clone root in a clone), reads `urd.json.engine` and imports the engine from the versioned folder, exactly as `tests/_engine.mjs` and `editor/scripts/validate.mjs` do (ADR-0013). The tool lists are derived from the engine's own registries, never from copied lists, so a new block type appears in `urd_block_types` without anyone editing anything. `mcp/**` is `ownedPaths`, so the updater keeps the server in step with the engine in the same commit.

## Consequences

- **Placement in `template/` is a deliberate choice.** After «Use this template» the clone's root equals `template/`, so `mcp/server.mjs` and `.mcp.json` end up in the root of the site owner's repo and are found by the agent client without installation. Had the server been outside `template/`, it would never have reached a single cloned site and would have been an Urd developer tool instead of a product feature.
- **Ownership:** `urd.json.ownedPaths` gets `mcp/**`, mirrored in `OWNED_PATTERNS` in `guard.js` (the contract test requires identical lists). `.mcp.json` is classified EXPLICITLY as an exact path: the completeness test filters out dotfiles, so an unclassified `.mcp.json` leaves a hole no test shouts about. `isAllowedPath` already rejects both without change, so publishing can never write the MCP server.
- **One source consolidation is required:** `RESERVED_SLUGS` is today module-private in `guard.js` and duplicated in the editor. A third copy is unacceptable, so the constant is exported from `guard.js` and imported by the MCP server.
- **The site owner must have `node` installed** to run the server. The promise «cloned sites never need npm» stands, but this is the place Urd is closest to the line, and it shall be stated explicitly in the setup guide.
- **Privacy:** the server sends the site's content to whichever LLM service the site owner's client uses. Urd cannot control that, only be clear: it is stated in plain words in the setup guide and in the server's own startup message. The technical counterweight is the path guard, which prevents the server from reading `.dev.vars`, `.env` or anything outside the site root, tested explicitly against `..`, absolute paths and dotfiles.
- **The `mcp/` files are served publicly** by Cloudflare Pages as inert source code without secrets. `/mcp/*  X-Robots-Tag: noindex` is added to `_headers` alongside `/admin/*`, but `_headers` is permanently exempt from the updater (ADR-0014), so existing sites get the line only via the diff instruction.
- **The sanitisation is duplicated,** and that is the design's clearest drift point. `stripActiveContent` in `engine/sanitize.js` is DOM-based and cannot run in Node, so the MCP side needs a text-mode counterpart. The two must have a corpus-based parity test from day one, not as a cleanup afterwards.
- **The residual risk is valid but ugly content** (overlapping blocks, text outside the frame), not invalid JSON: the schema covers the form, and `migrate.js` turns unknown types into neutral placeholders with the data preserved instead of crashing. The tool descriptions therefore instruct the agent to ask the site owner to look at the site in `/admin` afterwards.
- **Testing** lives in `tests/mcp-*.test.mjs`: the dispatcher as a pure function against fixture messages, the tools against a temporary site root under `os.tmpdir()` (never against real content), the invariant tests (no npm import, no `fetch`/`node:http`/`node:child_process`, no import of `mcp/` from outside, the block types derived from the `blocks/` folder equal to the `define` calls in `urd.js`), plus one integration test that spawns the server and does `initialize` and `tools/list` over pipes. Schema parity against `schema/`, on the other hand, belongs in `editor/scripts/validate.mjs`, since ajv lives in `editor/node_modules`; CI already runs `npm run validate`, so drift is caught automatically.
- **The two other routes are not rejected for good.** An admin assistant requires its own ADR for the extension point and the key management (where routing through a Pages Function with the key as a Cloudflare secret is far stronger than localStorage, since the CSP then remains `'self'`), and it SHALL in that case share the write layer with the MCP server. The browser's built-in AI can come as a small, feature-detected addition once the relevant APIs are stable.
